* std/random — random numbers

#+BEGIN_SRC scheme
(import (std random))

(random-int 1 6)                          ;; the calling thread's generator
(random-int 1 6 #:rng my-source)          ;; one of your own
(with-random-seed 42UL (deal-a-hand))     ;; a run that replays
#+END_SRC

ChaCha20, seeded with 256 bits from the OS CSPRNG, one generator per thread.
The default path locks nothing and shares nothing, so drawing from two threads
at once costs what drawing from one costs. A source you make yourself is locked
instead, once per operation.

Every function takes ~#:rng~, defaulting to ~(parameter-ref current-random)~.

** The ambient source

~current-random~ is a ~(Param RandomSource)~, and its value holds *no
generator*. It names the calling thread's, and decides which one that is at the draw.

That is what makes the default safe on a bjoroutine. A fiber may resume on a
thread it did not suspend on, so a source read before a suspension and drawn
from after it would otherwise be reaching into a generator another fiber is
already inside. The ambient source has no state to race on.

** Drawing

- ~(random-int lo hi)~ : ~int~, *inclusive at both ends*. Lemire's method, so no
  modulo bias.
- ~(random-double)~ : ~double~ in ~[0, 1)~, 53 bits.
- ~(random-u32)~, ~(random-u64)~ : the raw words.
- ~(random-bool)~ : one bit, taken 64 at a time.
- ~(random-chance? p)~ : true with probability ~p~. Outside ~[0, 1]~ it is the
  nearer end and costs no draw.
- ~(random-bytes! bytes)~ : fills an ~(Array byte)~ in place. Whole blocks go
  straight into it, so this is how to ask for many bytes at once.
- ~(shuffle-array! a)~ : Fisher-Yates, in place. Answers nothing.
- ~(shuffle-vec v)~ : answers a new ~Vec~ and leaves ~v~ alone.
- ~(random-ref v)~ : an element of a ~(Vec %a)~. Raises on an empty one.
- ~(random-string n)~ : ~n~ characters of ~[A-Za-z0-9-_]~.
- ~(random-string/chars n alphabet)~ : the same over a ~(Vec char)~ of your own.
  Raises on an empty alphabet.

** Making a source

- ~(make-random)~ : 256 bits from the OS. Unpredictable, and the one to reach
  for.
- ~(make-random/seed64 s)~ : reproducible. The 64 bits are stretched to the
  256-bit key by SplitMix64, so only 2^64 of the generators are reachable.
- ~(make-random/seed256 a b c d)~ : reproducible, at the full key width. Four
  words, so there is no malformed seed.
- ~(random-split r)~ : an independent generator, drawn from ~r~. On the ambient
  source it draws from the calling thread's. This is how a fiber gets one of its
  own.

** Binding one

- ~current-random~ : the parameter. ~parameterize~ it and every call that did not
  name a source follows.
- ~(with-random-seed 42UL body ...)~ : that ~parameterize~, with a
  ~make-random/seed64~ in it.

** What to watch out for

- *A bound source is safe to share, and still does not replay.*

  #+BEGIN_SRC scheme
  (parameterize ((current-random (make-random/seed64 42UL)))
    (bjo (worker))     ;; these two share one generator, under its lock:
    (bjo (worker)))    ;; safe, but the order they draw in is the scheduler's
  #+END_SRC

  Every operation on a source you made takes that source's lock, so no draw is
  lost, doubled or torn however the fibers interleave. What the lock cannot give
  is the thing the seed was for: the stream is one deterministic sequence, but
  which fiber gets which value of it is not. Give each fiber
  ~(random-split (parameter-ref current-random))~, or a seed of its own, and the
  run replays.

  The default source needs neither, being one generator per thread and reached
  by no other.

- *The lock is per operation, not per draw.* ~shuffle-array!~ and
  ~random-bytes!~ are many draws, and take it once — so a shuffle is the
  permutation the stream describes rather than one interleaved with another
  fiber's. It also means an operation on a shared source holds it for as long as
  the operation takes: shuffling a million-element array under a source two
  fibers are drawing from will make them wait.

- *Binding a seeded source makes everything under it predictable*, including
  code you did not have in mind when you wrote the ~parameterize~. A session
  token minted inside the extent of a ~with-random-seed~ is guessable. Keep the
  extent to the thing being replayed.

- *Seeded means reproducible, not unguessable.* ~make-random/seed64~ and
  ~make-random/seed256~ take what they are given. Use ~make-random~, or the
  default, for anything anyone else must not predict.

- *~random-int~ includes ~hi~.* ~(random-int 0 (vec-length v))~ is off the end;
  ~(random-int 0 (- (vec-length v) 1))~ is the index you meant, and
  ~random-ref~ is the one to use anyway.

- *~random-ref~ is ~Vec~-only.* Indexing a value generic over ~Collection~ and
  ~Refable~ would need ~Refable~'s ~%index~ pinned to ~int~, which a ~where~
  clause cannot say.

- *The two shuffles differ in what they answer*, not only in what they touch:
  ~shuffle-array!~ writes the array it was given, ~shuffle-vec~ hands back a new
  vec because a ~Vec~ cannot be written.
