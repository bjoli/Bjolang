* Bjolang - a language

I think we have all had the thought: all programming languages suck in at least one way. Not all of us think it is a big deal, but some of us feel the urge to try our wings at designing a language. This is my 95% vibe coded try. Not really meant for real use, but to see if my thoughts made any sense.

* Elevator pitch
Bjolang is a scheme-inspired language with local HM type inference that bjompiles to constipated c#. It has traits instead of classes, meaning you don't ever have to think about two-way interop. The default bjollections are immutable. A fast RRB tree (Vec), a very fast CHAMP (hash table), a linked list (List). There are more datastructures coming (bjordered map, deque, queue).

It also fakes Brand/higher kinded types by inlining traits when the trait is known at compile time, giving us among other things, a Monad trait. It is eager and non-curried, but has a bjombda shorthand.

It has concurrentML. 

* Greatest hits

The things I am most smug about, in descending order of smugness.

*** Concurrency: bjoroutines and first-class events

Bjolang has ConcurrentML. And by that I mean: WOOP WOOP WAKE UP, BJOLANG HAS CONCURRENTML. No async. No Task. No go channels or goroutines. We have bjo channels and bjoroutines. And not only that, it competes with go on allocations and speed, while being actually expressive. 

It is fully cooperative, and yields control when calling other bjoroutines or when syncing on channels. 


#+begin_src scheme
;; A suspending function. defbjo defines a bjoroutine
(: producer (-> (Chan int) int void))
(defbjo (producer ch n)
  (let lp ((i 0))
    (if (= i n)
        (sync (chan-send ch -1))
        (let ((sent (sync (chan-send ch i))))
          (lp (+ i 1))))))

;; A select-style worker. `chan-recv` returns an event -- it does not
;; suspend -- which is why two of them can be built and handed to `choose`
;; before either has happened.
(type (: WorkerMsg (Union (Job int) Quit)))
(: worker (-> (Chan int) (Chan bool) (Chan int) void))
(defbjo (worker jobs cancel results)
  (let lp ((total 0))
    (match (sync (choose (wrap (chan-recv jobs)   (fun (j) (Job j)))
                         (wrap (chan-recv cancel) (fun (c) Quit))))
      ((Job j) (lp (+ total j)))
      (Quit    (sync (chan-send results total))))))

;; A timeout is just another branch. `guard` rebuilds the event at each
;; sync, so the deadline is not stale after the first iteration.
(sync (choose (wrap (chan-recv ready)  (fun (v) (Job v)))
              (wrap (timeout 30000)    (fun (u) Quit))))

;; `always` and `never` are the unit and zero.
(sync (choose (never) (always 5))) ;; => 5
#+end_src

Spawning: ~(bjo expr)~ enqueues and returns a ~(Promise %a)~ without ever suspending, so a plain ~defun~ may spawn. Only /joining/ needs a bjoroutine, because joining is what waits. Operands to any (bjo ...) is evaluated before spawning.

#+begin_src scheme
(: start-work (-> int (Promise int)))
(defun (start-work x) (bjo (work x)))

;; Failure arrives as a value. "the operation failed" and "the fiber died"
;; are different facts, and a supervisor needs the difference.
(match (sync (promise-join p))
  ((Ok v)  v)
  ((Err e) 0))
#+end_src

And when the waiting has to happen in a plain ~defun~ after all -- a ~main~ that is not a bjoroutine, or a library that cannot dictate what colour its callers are -- ~sync/blocking~ is the door out. It takes any event and parks the calling thread instead of suspending a fiber, so channels, promises and timeouts are all reachable from ordinary code:

#+begin_src scheme
(defun (main args)
  (def ch (make-chan))
  (ignore (bjo (chatter ch)))
  ;; Building an event is pure, so everything still composes before it
  ;; gets here -- which matters, because nothing withdraws a
  ;; sync/blocking once it has parked.
  (match (sync/blocking (choose (wrap (chan-recv ch) (fun (v) (Got v)))
                                (wrap (timeout 1000) (fun (u) TimedOut))))
    ((Got v)  (println v))
    (TimedOut (println "nothing came")))
  0)
#+end_src

It is the mirror of ~blocking~, which carries a thread-parking call *into* fiber-land; this carries an event *out*. Do not use it from inside a bjoroutine: it would park a pool thread, which is what the events being waited for need in order to fire. Inside a bjoroutine the answer is ~sync~, which is the whole reason there are two.


*** Calling .NET async without ever meeting a Task

~Task~ is not a Bjolang type. You define #:async on import and use them as CML functions.

#+begin_src scheme
(import/extern
  (pause (: System.Threading.Tasks.Task.Delay (-> int void) #:async))
  ;; no CancellationToken overload exists? say so.
  (raw-pause (: System.Threading.Tasks.Task.Delay (-> int void)
                #:async #:uncancellable))
  ;; failures as values instead of as stack unwinding
  (fetch (: System.IO.File.ReadAllTextAsync (-> string string)
            #:async #:exceptions (System.IO.IOException))))

;; a .NET async call as a losable branch
(sync (choose (wrap (task->event (fetch "/etc/hostname")) (fun (s) (Job 1)))
              (wrap (pause 30000)                       (fun (u) Quit))))
#+end_src

*** Macros
Bjolang supports hygienic macros based on implicit-renaming. Together with syntax-match, thing brings about 90% of what syntax-case brings: An anaphoric if could look like this, for example:

#+BEGIN_SRC scheme
(def/macro (aif form compare inject)
  (syntax-match form
    ((_ test true-branch false-branch)
     #'(match test
        ((Some ,(inject 'it)) true-branch)
        (_ false-branch)))
    (_ (syntax-error "aif needs 3 forms"))))

;; which is then used like this
(aif (maybe-get-string)
     (println it)
     (println "fail"))
#+END_SRC

The main limitation is that macros cannot be used in the same module.

*** Nothing gets dropped by accident

Every non-~void~ (or non-unit) value in statement position must be used. If not you need to use (ignore ...). Ignore is a trait function, so it can do the right thing when ignoring things like promises.

#+begin_src scheme
(defun (main args )
  (+ 1 2) ;; ERROR

  (ignore (+ 1 2))              ;; blanket impl: drops it
  (ignore (.Append sb "a"))     ;; fluent .NET stops being a footgun
  (ignore (bjo (work 21))))     ;; Promise's impl detaches the fiber

;; Receipt has its own impl, so the discard site actually runs code
(def/impl (Discard Receipt)
  (defun (ignore r) (set! receipts-filed (+ receipts-filed 1))))

;; and Result is in the no-discard set, so this is a compile error:
;; (ignore (open-input-file "x"))
#+end_src

*** Pattern matching that knows about the CLR

~(:is Type binder)~ is a .NET type test in pattern position, and the binder is narrowed to that type afterwards. Which also means ~try~ can discriminate on exception type the same way ~match~ does.

#+begin_src scheme
(match (thing :> Object)
  ((:is System.String s) (string-length s))
  ((:is Exception e)     (.-Message e))
  (_                     "no idea"))

(try (risky-thing)
  #:catch ((:is System.IO.FileNotFoundException e) "missing")
          ((:is Exception e)                       "other")
  #:finally (cleanup))
#+end_src

*** Traits
Bjolang has traits. Traits can be regular traits, which means they are usable on concrete types (fast calls) or in dynamic contexts (as fast as C# Interfaces). There are also inlinable traits. These are traits that only work when the type is known at compile time, and are inlined at the call site. This is because c# cannot represent something like the Monad trait interfaces. Inlining solves this. These traits are painfully monomorphic.

#+begin_src scheme
;; The simplest kind of trait is something like a trait that
;; turns any thing into a string:
(def/trait (Printable %i)
  (: ->str (-> %i string)))

(def/impl (Printable int)
  (defun (->str i) (int->string i)))

;; More complex traits also work:
(def/trait (Foldable %col)
  ;; associated type
  (type %item)
  ;; fold is a function that takes:
  ;; 1. a function that takes an accumulator type, an item type and
  ;;    returns an item type.
  ;; 2. an accumulator type
  ;; 3. a collection type
  ;; 4. and returns an accumulator type.
  (: fold (-> (-> %acc %item %acc) %acc %col %acc)))

;; Implement the trait for a List with a generic in it
(def/impl (Foldable (List %a))
  ;; the associated type %item is the same as the %a in the list
  (type %item %a)
  (defun (fold f acc col)
    (list-foldl f acc col)))

;; fold is now a function that works on a list and any other data
;; type for which Foldable is defined.
(fold #(+ % 1) 0 '(1 2 3 4))

;; This is a "fake hkt" trait: it only works when types are
;; know at compile time and in monomorphic functions.
(def/trait (Functor (%f %a))
  (: fmap (-> (-> %a %b) (%f %a)  (%f %b))))

(def/impl (Functor (List %a))
  (defun (fmap g xs) (list-map g xs))) 

(def/impl (Functor (Option %a))
  (defun (fmap g o)
    (match o ((Some v) (Some (g v))) (None None))))

;; An implementation may also hold only *conditionally*: a list is
;; printable where its elements are. The where clause is not a note
;; to the reader — it is a dictionary the implementation carries, so
;; the element's own impl is what runs, chosen where the element type
;; is known rather than baked in at %a.
(def/impl (Printable (List %a))
  (where (Printable %a))
  (defun (->str xs) (list->str xs)))

(defun (main args)
  (def a-list '(1 2 3 4))
  (def an-option (Option 5))
  ;; these both work
  (def b (fmap #(+ &1 1) a-list))
  (def c (fmap #(+ &1 1) an-option))

  (defun (bump bomp)
    (fmap (fun (arg) (+ arg 1)) bomp))

  ;; Works, BUT locks bump into the type (List int)
  (def d (bump a-list))
  ;; Which means this fails because any function written against
  ;; an "inline" trait is going to be monomorphic. 
  (def e (bump an-option))
  0)

#+end_src

*** Keyword arguments
Unlike f#, bjolang has keyword arguments (but no optargs!):

#+begin_src scheme
(: key-fun (-> Int (#:what string) Void))
(defun (key-fun times #:what (string-append "ban" "ana"))
  (let loop ((times times))
    (when (> times 0)
      (println what)
      (loop (- times 1)))))

(key-fun 100) ;; prints "banana\n" 100 times
(key-fun 10 #:what "orange") ;; prints "orange\n" 10 times
#+end_src

You can use arbitrary expressions as default values for keyword args. If the function only takes c# literals, it is transformed into a c# named parameter call. If no parameters are used, a body that just binds the names is picked over one that checks which are used. The slow path does some Option unpacking. 

*** Structs and records
Have the same syntax, and both are constructed by naming the type — there is no f#-esque guessing at which type a bag of field names belongs to. This is a record example:

*** A proper looping facility

I got tired of shitty looping facilities a long time ago. I took Alex Shinn's (chibi loop) and made (goof loop) for guile scheme. Not only was it extensible and much more flexible than most looping facilities, it also had the fantastic feature that the code it produced was as fast as a hand-rolled loop (looking at you, python's for loop).

Bjolangs loop is based on what I learned writing goof-loop, but instead of using macros, it uses traits meaning it sucks a bit more. 

#+begin_src scheme
(defun (main args)
  (def my-vec (get-a-huge-vec))
  (def my-list (get-an-equally-huge-list))
  (loop (:for a my-vec)
        (:for b my-vec)
        (:break (= a (* b 2)))
        (:when (not (= a b)))
        (:acc acc (listing (+ a b)))))
#+end_src

It also supports subloops. Anything that isn't a for clause followed by a :for clause starts a subloop:

#+begin_src scheme
(defun (main args)
  (loop (:for a '(1 2 3))
        (:acc acclst (listing (* a a)))
        (:when (odd? a))
        (:for b [1 2])
        (:acc accvecc (vectoring (a . b)))))
;; => (1 4 9)
;;    [(1 . 1) (1 . 2) (3 . 1) (3 . 2)]
#+end_src

 And the best part? It is fast.

 Oh, and it also has a seq version

 #+begin_src scheme
(defun (main args)
  (def all-fibs
    (seql (:with a 0L b)
          (:with b 1L (+ a b))
          (:yield a))))
  (println "I wonder if we can print all the fibonacci numbers up to 2^64-1")
  (seq-for-each #(println &) all-fibs))
 #+end_src


*** Constructorless DSLs

Lists, quasiquoted lists and vectors do not need constructors in some circumstances, giving us nice small DSLs. Like the (std fmt) string formatter, bringing string formatting into the 1980s:

#+begin_src scheme
;; Check Examples/receipt.bjo for the full source
;; This is our list of lines, Line being a record
(: basket (List Line))
(def basket
     ;; This could of course be function, like
     ;; (line "bananas" 1.24 24.90) or a list of tuples like
     ;; (map mkline (list ("banana" . 1.24 . 24.90) ...))
  (list (Line (what "Bananas, organic") (qty 1.24) (unit 24.90))
        (Line (what "Coffee beans, dark roast, whole") (qty 2.0) (unit 89.00))
        (Line (what "Rye bread") (qty 1.0) (unit 32.50))
        (Line (what "Oat milk") (qty 3.0) (unit 18.95))
        (Line (what "Cloudberry jam from Lapland, the small jar") (qty 1.0) (unit 64.00))))

(: receipt (-> (List Line) (Vec Block)))
(defun (receipt ls)
  (let* ((total (list-foldl (fun (acc l) (+ acc (amount-of l))) 0.0 ls))
         (net (/ total 1.12))
         (vat (- total net)))
    ;; cloudberry jam gets truncated, with "..."
    [(with-fmt current-ellipsis "..."
       ;; first print the heading.
       [(heading ["BJOLI'S GROCERY"])
        nl ;; Newline
        masthead ;; formatted header
        (rule #\=) ;; ruler with the = char
        (joined item ls []) ;; item is a formatter for Lines
        (rule #\-) ;; ruler with -
        ;; labelled is a function (see receipt.bjo) that prints
        ;; the first argument left justified and the second
        ;; right justified
        (labelled ["Net"] net)
        (labelled ["VAT 12%"] vat)
        (rule #\=)
        ;; function that pads a value with "TOTAL" and ...
        ;; until it fills the complete width
        (total-line total)
        nl ;; newline
        ;; prints three columns, rate, net and vat
        (vat-summary net vat)
        nl
        ;; justified footer
        footer])]))

(defun (main args)
  (show (receipt basket))
  0)

And any declared (Vec block), also a def, gets this treatment, so any function that needs formatted strings can use this.

The same machinery gives (std run) its shell notation. A form is one thing to run, spelled as a list of words whose first word says what it is: a program, or one of the tags pipe, from-file, into-file, append-to-file, errors-into-file and errors-append-to-file. Stages can be procedures of your own:

#+begin_src scheme
(import (std run))

;; A Filter is a bjoroutine that takes an input port, an output port and returns unit
;; It can be used in the run pipeline
(: shout Filter)
(defbjo (shout in out)
  (write-string out (string-upcase (read-all in)))
  unit)

;; An ordinary defun. Waiting for a program blocks rather than suspends, the way
;; read-all on a file port does, so shelling out does not turn its callers into
;; bjoroutines. From inside one, go through (blocking ...).
(defun (main args)
  ;; A single command is a single form - no wrapper.
  (match (run/string '(uname -r))
    ((Ok s) (display s))
    ((Err e) (displayln "no")))

  ;; Symbols, strings, ints and doubles are all words, so -n and 2 need no
  ;; quoting. A pipeline has to say pipe: a list of stages is never guessed at.
  ;; a filter can be used anywhere in the pipeline.
  (match (run/string '(pipe (cat "/etc/passwd") (grep "root") ,shout (head -n 2)))
    ((Ok s) (display s))
    ((Err e) (displayln "no")))

  ;; Redirection nests around whatever it applies to, and a program taking no
  ;; arguments is just its name.
  (match (run/status '(into-file "roots.txt"
                        (from-file "/etc/passwd"
                                   (pipe (grep "root") sort))))
    ((Ok code) (displayln "written"))
    ((Err e) (displayln "no")))

  ;; ,(cmd ...) for when the program name is computed rather than spelled, and
  ;; [...] to splice a computed argv.
  (def tool (list-head args))
  (match (run/strings '(pipe (git ["log" "--oneline"]) ,(cmd tool "-l")))
    ((Ok lines) (displayln (string-join lines "|")))
    ((Err e) (displayln "no")))
  0)
#+end_src

An error in the argument is going to be discovered at RUNTIME. The run DSL has no type safety in that regard.
