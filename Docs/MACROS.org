* Macros

A macro is a function the compiler runs while it is parsing. It takes the form
that was written and returns the form to read instead.

#+BEGIN_SRC scheme
;; in macros.bjo
(def/macro (or-else form inject compare)
  (match form
    ((SList (Cons _ (Cons a (Cons b Nil))))
     #'(let ((tmp ,a)) (if (= tmp 0) ,b tmp)))
    (_ (syntax-error form "or-else takes two arguments"))))
#+END_SRC

#+BEGIN_SRC scheme
;; anywhere else
(import "macros.bjo")

(or-else (lookup k) 0)
#+END_SRC

** A macro lives in another module

A transformer is compiled code, so it has to exist before it can run. Its module
is compiled to a ~.dll~, loaded into the compiler process, and the transformer
invoked by reflection while the *using* module is being parsed. That is the
Template Haskell arrangement and it has the same consequence: a macro cannot be
used in the module that defines it, and an ~(include ...)~ does not help, since
an included file becomes part of the including one.

Using one where it is defined is reported as that, not as an unbound name.

A transformer may call anything its own module can — the prelude, a third
module, its own helpers — because the compiler loads its module's dependencies
alongside it. Note what that means: the compiler is running compiled Bjolang
code, so a transformer that does not terminate hangs the build, and anything its
module imports has to be loadable in the compiler's process.

** ~Syntax~

The type a transformer takes and returns. It is an ordinary Bjolang value: it
can be built and matched anywhere, with no macro in sight.

| Case              | Is                                             |
|-------------------+------------------------------------------------|
| ~(SSym s)~        | an identifier                                  |
| ~(SDatum s)~      | a quoted symbol written as data — ~'foo~       |
| ~(SInt text)~     | a numeric literal, as written                  |
| ~(SStr text)~     | a string literal                               |
| ~(SChar c)~       | a character literal                            |
| ~(SKey k)~        | a keyword — ~#:when~                           |
| ~(SList items)~   | a parenthesized form, holding a ~(List Syntax)~ |
| ~(SPunct text)~   | ~,~ ~,@~ ~:~ ~.~ ~...~, which survive reading  |

~SList~ carries a real list, so ~map~, ~fold~, ~length~ and the trailing rest
pattern all work on a macro's input:

#+BEGIN_SRC scheme
(match form
  ((SList (Cons _ (Cons only Nil))) ...)   ;; exactly one argument
  ((SList (Cons _ rest)) ...))             ;; any number
#+END_SRC

~SSym~ and ~SDatum~ carry the same payload and differ in one thing: hygiene
renames the first and never the second.

Also available: ~(syntax->string s)~, which renders back to something that reads
as source; ~(syntax-file s)~ and ~(syntax-line s)~; ~(syntax-ident=? a b)~, which
is ~compare~ as a function rather than as a parameter; and ~(syntax-error form
msg)~, which is how a transformer rejects its input. ~syntax-error~ types as a
~Syntax~ so it can sit beside the arms that return one, and never returns — the
expander catches it and reports it against the macro's call site.

** ~#'~ builds a template

~#'form~ is syntax-quote. It is spelled differently from ~'(...)~ because the
two build different things: ~'(a b)~ is a list literal and is homogeneous, while
a template is heterogeneous by nature.

| In a template | Becomes                                    |
|---------------+--------------------------------------------|
| ~foo~         | ~(SSym 'foo)~ — an identifier, renamed     |
| ~'foo~        | ~(SDatum 'foo)~ — a datum, never renamed   |
| ~1~ ~"s"~ ~#\c~ ~#:k~ | the matching literal case          |
| ~(a b)~       | a nested ~SList~                           |
| ~,x~          | splices ~x~, which must be a ~Syntax~      |
| ~,@xs~        | splices a ~(List Syntax)~ in place         |

The distinction between ~foo~ and ~'foo~ is also why ~''foo~ is never needed,
which is just as well, since it does not read.

** ~syntax-match~ takes one apart

~#'~ builds a form and ~syntax-match~ reads one. It is a macro like any other,
in ~std/syntax-match~, and it is what a macro should be written in:

#+BEGIN_SRC scheme
(import (std syntax-match))

(def/macro (my-let form inject compare)
  (syntax-match form
    ((_ ((name value) ...) body ...)
     #'((fun (,@name) ,@body) ,@value))
    (bad (syntax-error bad "my-let takes a binding list and a body."))))
#+END_SRC

A pattern is one of:

| Pattern         | Matches                                                |
|-----------------+--------------------------------------------------------|
| ~_~             | anything, binding nothing                              |
| ~name~          | anything, binding it to ~name~                         |
| ~'name~         | the identifier ~name~ — what ~compare~ tests           |
| ~1~ ~"s"~ ~#\c~ ~#:k~ | that literal                                     |
| ~(p q)~         | a form of exactly that many items                      |
| ~(p q ...)~     | a form of at least that many, the rest each matching ~q~ |

The last is the ellipsis, and there are two kinds of it. Over a *variable* —
~body ...~ — it binds the tail, which is the trailing rest pattern a ~match~
already has. Over anything else — ~((name value) ...)~ — every remaining item has
to match that pattern, and each of *its* variables is bound to a list of what it
matched, one entry per item. That is not a shape a ~match~ pattern can express,
which is the reason this exists: the same macro written against ~Syntax~ directly
is a fold and two lists by hand.

Ellipses nest. ~((head arg ...) ...)~ binds ~head~ to a list and ~arg~ to a list
of lists, as deeply as the pattern goes.

A clause becomes one arm of one ~match~, so a pattern's failure — of either kind
— falls through to the next clause. The whole form is that ~match~ and nothing
else: what a clause cannot say by shape becomes its ~#:when~, and an ellipsis
over a compound becomes a fold through ~all-of~, which ~std/syntax-match~
exports for that purpose.

A last clause spelled ~_~ or a plain variable covers the input. Without one,
~syntax-match~ adds an arm that reports the form no clause matched — so a macro
that only accepts one shape need not write the rejection, though writing one buys
a message that can name the macro.

Two things it will not accept. A ~...~ anywhere but last, because it repeats what
precedes it; and a pattern that binds one name twice, which would be a shadowing
~let~ rather than the equality test it looks like. An uppercase name is refused
too: it would be an ordinary variable, so ~(Cons a b)~ as a pattern would match
every three-element form rather than a cons — write ~'Cons~ for the identifier.

** Hygiene

Everything the transformer *constructs* is renamed apart from the call site.
Everything it took from the input is left exactly as written. Both halves matter:

#+BEGIN_SRC scheme
(def tmp 9)
(or-else 0 tmp)   ;; 9
#+END_SRC

The template binds ~tmp~ and the caller passes one. Without renaming, the ~,b~
spliced into the template would land inside the template's own ~let~ and read
its temporary. With it, the template's ~tmp~ becomes a name nothing at the call
site can spell, and the caller's ~tmp~ still means what it meant where it was
written.

Renaming is a fresh name per template identifier per invocation, so two
expansions of the same macro never share one. A renamed identifier is then an
*alias resolved at parse time*, in this order:

1. If the expansion binds it, ordinary scoping does the work.
2. Otherwise, if the macro's module exports it, it resolves to that module —
   spelled ~Module_Module::name~, which no local at the call site can shadow.
   This is what lets a template call a helper of its own module.
3. Otherwise the rename is stripped: a prelude binding, a data constructor, or a
   special form. Rule three is what lets a template write ~let~, ~if~ and ~->~
   unchanged.

Diagnostics report names with renames stripped, so a message names what was
written rather than a name that appears in no source file.

*** ~inject~

The one deliberate hole, and the only way to make one. ~(inject 'it)~ builds an
identifier that is *not* renamed, so it binds at the call site — which is how an
anaphoric macro introduces a name the caller can see. It takes identifiers only.

*** ~compare~

~(compare a b)~ is true when two identifiers are the same one. It is base-name
equality after mark stripping and not more: at parse time there is no call-site
scope to consult, so ~(compare (car clause) #'else)~ is true when the caller
wrote ~else~ even if the caller had locally rebound it. That covers the
~cond~-like idiom it exists for; it is not denotational equality.

** Recursion

Two different things go by that name here, and only one of them is Scheme's.

*A template may call the macro it is in.* The expander reads what a transformer
returns, so a macro call in the result is expanded like any other — which is how
a form of any length is taken apart, one item per round:

#+BEGIN_SRC scheme
(def/macro (any-of form inject compare)
  (syntax-match form
    ((_) #'0)
    ((_ only) only)
    ((_ first rest ...)
     #'(let ((tmp ,first)) (if (= tmp 0) (any-of ,@rest) tmp)))))
#+END_SRC

That is the ~syntax-rules~ shape, and it behaves the way it does there. Each
round is a separate invocation, so each renames its own ~tmp~ and no level can
capture another's or the caller's. Two macros may do it to each other, and a
template may expand to a *definition* as well as to an expression: ~def~ and
~defun~ are read by the body parser rather than by the expression parser, and a
renamed one is understood in both places.

Note that the recursion is the *expander's*, not the transformer's: the call in
the template is expanded when the result is read, so nothing is nested inside
anything at the time the transformer runs.

*A transformer is a program, so it can just recurse.* This is the one
~syntax-rules~ cannot do, and it is usually the better answer:

#+BEGIN_SRC scheme
(: cond-arms (-> (List Syntax) Syntax Syntax))
(defun (cond-arms clauses whole)
  (match clauses
    (Nil (syntax-error whole "cond needs a final (else ...) clause."))
    ((Cons clause rest)
     (syntax-match clause
       (('else body ...) (one-form body clause))
       ((test body ...) #'(if ,test ,(one-form body clause) ,(cond-arms rest whole)))))))
#+END_SRC

One expansion instead of one per clause, an error message that can say what was
wrong with the *seventh* clause, and no limit to how far it goes. ~cond~ in the
prelude is written this way.

Which is to say: reach for a template call when the recursion is on the shape of
the form, and for an ordinary function when it is on a list you already hold.

*Runaway expansion is caught.* A transformer that expands to a call to itself on
the same input never finishes, and nothing else would notice — the parser would
read expansions until the stack ran out, naming neither the macro nor the place.
So expansion is counted per call site, which every node a transformer builds
inherits, and the hundredth at one site is reported as a runaway. A recursion
that takes something off each round never reaches it.

** What a macro cannot do

- *Appear anywhere but where a whole expression or declaration is expected.* Not
  as a ~loop~ clause, a ~match~ arm, a ~let~ binding, a ~#:when~ guard, a
  pattern, or a type: those are read structurally by their parent and never
  reach the point where a head symbol is dispatched.
- *Shadow a special form.* Expansion is tried after every special form has
  failed to match, so a macro named ~if~ is never reached.
- *See types.* Expansion happens at parse time, before inference.
- *Be a value.* A macro name is not a binding at the call site: it cannot be
  passed, stored, re-exported, or used as a trait method.
- *Vary its signature.* A transformer takes exactly the form, ~inject~ and
  ~compare~. Type parameters, trait constraints, keyword or rest arguments and
  ~defbjo~ are rejected at the ~def/macro~, because each changes the emitted C#
  method that the expander reflects on.

Two more things worth knowing. Every node a transformer builds carries the *call
site's* range, so a type error inside a large expansion reports one line. And the
compiler runs user code: a transformer that does not terminate hangs the build,
which is what the hundred-level expansion limit is for.
