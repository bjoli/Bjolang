* Units of measure

A number can carry a dimension in its type: ~(double m/s)~, ~(rational m)~,
~(long cent)~. A dimension has one base unit, and every value of it is stored
in that base. Other units — ~km~, ~ft~, ~km/h~ — exist only at the edges: in
literals, in ~in~, in parsing and printing. The compiler converts at compile
time, exactly, and nothing of the unit is left at run time: a ~(double m/s)~
is a C# ~double~.

#+BEGIN_SRC scheme
(def/dimension length #:base m)
(def/dimension time   #:base s)
(def/unit km <1000 m>)
(def/unit ft <3048|10000 m>)
(def/unit h  <3600 s>)

(+ <1 m> <1 ft>)                    ; (double m), 1.3048
(+ <1 km> <1 s>)                    ; type error: length and time
(/ <100 km> <2 h>)                  ; (double m/s), 13.888…
(in (/ <100 km> <2 h>) km/h)        ; double, 50
(: v (rational m/s))
(def v <1 km/h>)                    ; 5/18, exactly
#+END_SRC

Nothing about SI is in the compiler. ~(std units)~ declares SI, and a program
that does not import it declares its own dimensions and units the same way.

** The model

*** A dimension has a base unit, and values are stored in it

~(def/dimension length #:base m)~ declares a dimension and its base unit. A
type names base units only: ~(double m)~ is "a length", stored in metres.
There is one type per dimension and carrier, so ~(+ (.distance l) (.climb l))~
works whatever unit each was written in.

~(def/unit km <1000 m>)~ declares a unit by its value in units already
declared. A unit has a *factor* to the base and a *term* over base units: ~km~
is 1000 × m, ~N~ is 1 × kg m/s², ~deg~ is π/180 × 1. A factor is a rational
times an integer power of π, so every conversion is exact until it is put
into a carrier.

- A unit whose factor is 1 is a name for its term: ~N~ is ~kg m/s^2~, and may
  be written in a type: ~(double N)~ is ~(double kg m/s^2)~.
- A unit with another factor, ~km~, may not be written in a type: "types use
  base units: write ~(double m)~, and ~(in x km)~ where a number in km is
  needed".
- A dimensionless unit has the empty term: ~(def/unit deg <1|180 pi>)~,
  ~(def/unit % <1|100>)~. ~<45 deg>~ is a plain number, 0.785….
- ~(def/prefix k 1000)~ makes ~km~, ~kg~, ~kPa~ from ~k~ and a unit, the first
  time something names them.

*** The carrier

The type of a quantity is a carrier and a base term: ~(double m/s)~,
~(rational m)~, ~(long bit)~. Any number type is a carrier.

A dimension may say which carrier its quantities have when nothing else says:

#+BEGIN_SRC scheme
(def/dimension money #:base cent #:carrier long)
(def/dimension information #:base bit #:carrier long)
(def/dimension angle #:base rad)                       ; no carrier: double
#+END_SRC

- ~#:carrier~ is a default. A type that names a carrier,
  ~(double cent)~, overrides it.
- A term over several dimensions takes the carrier they agree on: ~m/s~ is
  rational if length and time both are. If they disagree, or none is
  declared, the default is ~double~.
- A literal is converted to the base exactly, and then into the carrier:
  rounded once for ~double~, ~float~ and ~decimal~, kept for ~rational~, and an
  error for an integer type when it is not an integer:

| Carrier          | ~<1 km/h>~                       | ~<3 ft>~ in m                 |
|------------------+----------------------------------+-------------------------------|
| ~(rational m/s)~ | 5/18                             | 1143/1250                     |
| ~(double m/s)~   | 0.2777…, rounded once            | 0.9144, rounded once          |
| ~(decimal m/s)~  | 0.2777…, rounded once            | 0.9144                        |
| ~(int m/s)~      | error: 5/18 is not an integer    | error: 0.9144 is not an integer |

A program that wants exact integers in feet makes ~ft~ the base of a
dimension of its own.

~rational~ is a carrier like the others: a .NET struct that implements
~INumber~, so ~+ - * / <~ work on it as on ~double~. It is the one carrier that
keeps every conversion exact; it is also the slow one.

*** Type syntax

- ~(double m/s)~, ~(long kg m^2/s^2)~: a carrier and a unit expression over
  base units and factor-1 units. ~(double 1)~ is ~double~.
- ~<m/s>~: the unit with the default carrier. Written without spaces, since
  the reader reads it as one symbol: ~<kg*m/s^2>~.
- ~(double %u)~, ~(double %u^2)~, ~(double m/%u)~: a unit variable.
- In a type the unit expression is read by the S-expression reader, so it has
  no parentheses. A rational exponent is written with ~|~:
  ~(double Hz^-1|2)~. A denominator of several units is written by
  juxtaposition, which binds tighter than ~/~: ~(double m/s kg)~ is
  m/(s·kg).

*** Quantity literals

~<9.81 m/s^2>~: ~<~ directly followed by a digit, ~.~, or ~-~ and a digit, up to
the matching ~>~. ~(< 1 2)~, ~<=~ and ~<-~ are untouched. The reader gives
~(quantity "9.81" "m/s^2")~, a form that can also be written.

- The number is read exactly: ~0.1~ is 1/10, ~1|3~ is 1/3, ~1e-3~ is 1/1000.
- The value is number × the unit's factor, the type is the unit's base term
  with a carrier: the one the context asks for, else the default carrier.
- Codegen emits one constant, converted into the carrier.
- Inside ~<…>~ the text is read as written: spaces, parentheses, ~pi~.
  ~<0.351 mSv m^2/(GBq h)>~.

*** Leaving and attaching

- ~(in x km/h)~: the number ~x~ is in km/h. ~x~'s term and the unit's must
  be equal; the result is the carrier, unit 1. Emitted as one multiplication
  by a constant, or none when the factor is 1. On an integer carrier the
  factor's reciprocal must be an integer: ~(in x mm)~ on a ~(long m)~ is
  ×1000; ~(in x km)~ is an error that suggests a ~double~ or ~rational~.
- Attaching is multiplication: ~(* n <1 km>)~ is a length.
- There is no ~as~: there is only one unit per dimension in a type.

*** Arithmetic

- ~+ - %~ and ~negate~: ~(-> (num %a %u) (num %a %u) (num %a %u))~ with
  ~Num %a~. One unit, any unit.
- ~*~ and ~/~: the units multiply and divide. ~(* <2 m> <3 m>)~ is
  ~(double m^2)~. ~recip~ inverts the unit.
- The comparisons: ~(-> %a %a bool)~ with ~Ordered %a~, which a number with a
  unit has: its carrier's.
- ~sqrt~, ~cbrt~: ~(double %u^2) → (double %u)~, ~(double %u^3) → (double %u)~.
- ~sin~, ~exp~, ~log~, ~floor~, ~round~ and every other .NET method: unit 1.
- A plain literal is a number of unit 1, except zero, ~0~, ~0.0~, ~0M~,
  which is a number of every unit: ~(> x 0)~ works for lengths. ~(> x 1)~
  does not: "write ~<1 m>~".

~Num~ is asked of the carrier, never of the number with its unit, and ~Num~
itself does not hold at a unit other than 1. ~(sqr x)~ at ~(-> %a %a)~ with
~(* x x)~ inside is wrong for metres, which square to m², so a function
generic over ~Num~ neither changes nor accepts quantities: "a number with a
unit is not a Num". A function that is correct at any unit says so with a
unit variable: ~(-> (double %u) (double %u) (double %u))~. ~abs~, ~min~,
~max~ and the other ~Num~ methods stay at unit 1 until Phase 10.

*** Declarations

#+BEGIN_SRC scheme
(def/dimension length #:base m)
(def/dimension money  #:base cent #:carrier long)
(def/unit EUR <100 cent>)
(def/unit N <1 kg m/s^2>)
(def/unit deg <1|180 pi>)
(def/prefix k 1000)
#+END_SRC

- They are compiler declarations, not macros: a literal three lines below
  ~(def/unit furlong …)~ uses it, and so does a type.
- A definition is a quantity literal over units already declared. Its number
  is exact; ~pi~ is a number in it.
- A base unit is an atom of the solver, keyed by the declaring module:
  ~std/units/m~. Two modules that each declare ~m~ have two units, as two
  types named ~Point~ are two types.
- They travel in the module metadata as data: dimension, base, carrier,
  factor, term.

*** Unit expressions

GNU's grammar, parsed by the compiler. Juxtaposition binds tighter than ~/~,
so ~kg m/s^2~ is kg·m/s² and ~m/s kg~ is m/(s·kg); ~*~ and ~/~ are left to right;
~^~ raises, with a rational exponent in parentheses (~Hz^(-1/2)~) or with ~|~
(~Hz^-1|2~); ~|~ divides two numbers before anything else, ~1|60~. A number in
an expression is a factor: ~<1 1|60 deg>~. Names are looked up exactly first,
then as a prefix and a unit, longest prefix first: ~min~ is a minute, not
milli-inch.

The run-time parser in ~(std units)~ (Phase 2) reads the same grammar.

** Where units are visible

A module sees the units, dimensions and prefixes it declares and those of the
modules it imports. ~(import (std units))~ brings SI; no import brings none.

- A unit in a type is stored in the metadata by its key, as a type is, so a
  module that never imported ~(std units)~ can hold, pass and return a
  ~(double m/s)~ it got from one that did.
- Writing a unit name — in a literal, a type, ~in~ or a definition — needs it
  in scope: "the unit 'm' is not in scope here. It is declared in
  (std units): write (import (std units))".
- The same name from two imports, with different keys, is ambiguous where it
  is used, and the error names both modules.
- ~only~, ~except~ and ~prefix~ on an import do not filter units yet: Open
  question 3.

** Decisions made, and why

- *A dimension has one base, and types name it.* Units of one dimension are
  one type, so ~(+ km-value m-value)~ needs nothing. The earlier design had
  ~(double km)~ and ~(double m)~ as two types with ~as~ between them; the
  paper programs showed the ~as~ moving around rather than going away.
- *The carrier is the user's.* A dimension may give a default. Rational
  everywhere would be exact and slow, and ~sqrt~, ~sin~, sensor data and π
  factors are not rational anyway.
- *Conversions are exact until the carrier.* Factors are rational × π^k in
  the compiler, and a literal or ~in~ is rounded once.
- *No unit is built in.* A program can do without ~(std units)~ and declare its
  own ~m~, as an int, with its own table.
- *The compiler parses unit expressions.* The earlier design called a
  Bjolang resolver through a hook. With types over base units only, what the
  compiler needs is a table lookup and a small grammar, and a hook would have
  made every unit-using program link a parser module.
- *Rational exponents.* ~sqrt~ of ~m~ is ~m^(1/2)~. Noise in V/√Hz is real.
- *~0~ is a number of every unit.* Kennedy's rule.
- *Non-linear conversions are outside the unit system.* Temperatures are
  newtypes (~Celsius~, ~Fahrenheit~) and logarithmic units are functions.
- *Rejected:* units as newtypes with a ~Unit~ trait and ~unit+~ (shapes like
  ~(Times Length Time)~ do not normalize); converting operators between
  ~km~ and ~m~ types (helps concrete code, not library code).

** Open questions

1. Printing. A ~(double m/s)~ is a ~double~ at run time, so ~(display v)~
   prints the number. Printing ~13.9 m/s~ needs the unit at the call:
   a synthesized ~Measured~ dictionary, or ~quantity->string~ as a special
   form. Phase 11.
2. A preferred unit for printing per dimension (~km/h~ for speed in a
   program about cars), and factor-1 names: ~Sv~ and ~Gy~ are both ~m^2/s^2~.
3. Units under ~only~, ~except~ and ~prefix~ imports.
4. Quantity kinds (torque against energy). A later layer.
5. A dimension whose carrier is a requirement, not a default
   (~#:carrier-only long~ for money).
6. Done in Phase 10: ~(num %c %u)~.

** Implementation plan

Each phase ends with its tests, the full suite green, and a commit. Phases
0–4 were done under the earlier design (units, not bases, in types). Their
code carries over: ~TNum~, the solver and erasure do not care whether an atom
is a base or not.

  ~sign~, ~zero?~) is checked at the carrier: those are .NET's members, and
  none multiplies. A function generic over ~Num~ is still refused.
- ~(num %c %u)~ in types (open question 6), and ~sqr~, ~positive?~ and
  ~negative?~ in ~(std maths)~ over it. Printed ~(num %a %u)~.
- Not done: ~summing~ and array ~sum~ at a unit. Their bodies add at a type

  lets ~+~ through is what they need.
- ~(std rational)~ is the built-in ~rational~ with functions by name:
  ~Rational~ is an alias of it, and ~rational+~ is ~+~. Written
  ~(: <1|3> rational)~ now, as the built-in is.
