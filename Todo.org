Known gaps, written down where they were found. One entry each: what, why it
matters, and the fix where one is known.

* CML: where the remaining speed is

~bench/Cml/Program.cs~ runs the ring at 58 ns/op on the same layer the language
runs at 112, so the cost is the seam between ~sync~ and the layer. Surgical,
separately measurable changes; ~IEvent<T>~ stays the spec. Unmeasured unless
noted.

- *Delivery is a callback where a fiber wants a slot.* ~EventAwaiter~ turns
  ~Publish~'s "call me" into "resume me" at a pooled object, a delegate hop and
  an interlocked handover (~13 ns). Tried once and regressed while per-park
  registration existed, which it no longer does. Try first.
- *A token cannot unregister.* ~Promise~ prunes waiters amortised, which is why
  ~FiberWatch~ needs a generation, an abandonment protocol and a fallback. An
  intrusive node the fiber unlinks deletes all three. Best value per risk.
- *A send carries a ~Unit~ it does not want.* ~ChannelSendEvent : IEvent<Unit>~;
  ~PutOp.ResumeGive~ exists only to avoid a closure (88 of 128 B/op).
- *Two ~Result~ types meet at every join.* ~promise-join~ allocates a ~Wrap~ and
  a mapper per join to convert ~Bjoml.Result<T>~.
- *Event ids use an interlocked increment* with one writer: eight atomics per
  eight-way ~choose~. A guess; measure first.
- *Unexplained: the direct-park rewrite regressed the ring.* Six explanations
  ruled out in ~design.md~. Needs ~perf~.

* Source mapping (~#line~)

- Hoisted temporaries inherit the directive of the statement before them; they
  want ~#line hidden~ (~emitStatement~'s prelude, ~hoistToTemp~, two paths in
  ~generateLocalFunction~). Harmless today by luck.
- Directives are emitted even when the line has not changed. A dedup must
  survive scratch buffers being relocated.
- Inlined trait methods keep the impl's ranges, so a trace names the impl and
  not the call site.
- Both build configurations keep a pdb, so its absence no longer tells a ~-d~
  build apart. Nothing depended on it.

* Diagnostics

- Errors from generalization, trait registration and parts of declaration
  checking carry a location only if their call site supplied one. Threading a
  ~Range~ into ~unify~ would close it.
- ~unify~ prints both types whole; it should point at the innermost mismatch.
- ~(Dict.)~ on a generic ~import/class~ says "cannot find the .NET type".

* Characters and strings

- ~char-foldcase~ is ~ToLowerInvariant~: differs from Unicode's simple fold for
  ß, ﬁ and the like.
- Numbers are read and written in the invariant culture only; there is no
  ~Culture~ to ask for ~1,5~. ~string->int~ still uses the ambient culture
  (only the sign can differ).

* Emacs mode (~bjomode.el~)

- A named loop aligns its clauses under the name, not under ~(:for~; needs a
  custom indenter (~lisp-indent-specform~ cannot express it).
- A ~match~ arm's body aligns under the pattern, as Emacs does for ~cond~.
- Library forms that read as bodies (~with-nack~) are not in
  ~bjo-indent-forms~.
- No completion, imenu or eldoc.

* Monomorphisation of constrained generics

Copies are made per ground instantiation, to a fixpoint, bounded by a code-size
budget (module size or ~budgetFloor~). Termination is by key; polymorphic
recursion cannot be written. The stdlib's 22 constrained generics have call
out-degree ≤ 1, so copies grow additively; largest demand 722 nodes
(~139_ord.bjo~). A branching graph would make the floor matter.

- *Every type argument must be ground*, so copies have no type parameters.
  Keeping unconstrained ones needs agreement with ~generalize~ on order. A
  function-typed argument is declined.
- *Suspending functions are not copied.* The twin is generated inside
  ~checkDeclGroup~, out of this pass's reach; ~Naming.specializedCopy~ already
  names it ~f__at_int__bjo~.
- *Mutual recursion is declined.* Specialising the whole group would also fix
  "Mutual recursion does not forward dictionaries".
- *A mention that is not a call is passed over.* Correct via eta-expansion.
- *A body that will not serialize is not published* (~try~, bare list literal,
  tuple destructuring, local function with keyword/rest parameters): calls keep
  their dictionary.
- *A published body is checked in the importer's scope*, so an importer's
  binding can be checked into the copy. Same seam as "A resolved call reads its
  arguments in the resolved name's scope".
- *A private helper a published body names becomes public* in the importer's
  scope (~doubled~ in ~193_lib.bjo~).

* Constraints and numerics

- *Mutual recursion does not forward dictionaries.* Direct recursion does
  (~Scope.SelfCall~); two constrained functions calling each other pass none
  and get CS7036. Fix: record type arguments for monomorphic recursive
  bindings. Nothing in the library does it yet.

* Colourless concurrency

- *A copy that never suspends is still emitted*, and it spreads: ~vec->list~ has
  a copy because ~vec-for-each~ is a ~defbjouble~, so every importer calling it
  gets copies too (all of samizdat's HTML writer; glasnost's ~folder-page~
  needed ~#:sync~). Pruning needs call sites redirected after selection.
- Two lambda pins (into a .NET ~Func~, into a structure of ground ~->~) get the
  generic ~Unpinned~ message. Unreachable from fixtures today.
- The lazy ~Seq~ functions have no suspending copy. Decided: the copy would
  return ~AsyncSeq~, a different function. ~port->chan~ instead.
- A ~(do ...)~ block cannot suspend: ~:bind~'s lambda colour is fixed. Would
  need ~:bind/bjo~ or a keyword on ~do~.

* Traits and macros

- *An impl at a concrete instantiation cannot be dispatched to.*
  ~(impl (Over (List int)) ...)~ emits non-generic ~Over_List~, and a dispatched
  dictionary is spelled ~Over_List<int>.Instance~ (CS0308). Not reproduced in
  October 2026, even with a recursive generic forcing dispatch; may be fixed.
- *A trait a macro's module imports is not among the ones it resolves.* The set
  comes from the module's own ~def/trait~s, so ~time-it~'s ~(->str ...)~ resolves
  where it expands. Fix: carry the set in module metadata.
- *A resolved call reads its arguments in the resolved name's scope.*
  ~unshadow~ applies to the whole application, so in
  ~(do (:bind x m) (:return (bind x)))~ the parameter ~bind~ means Monad's.
  Fix: infer callee and arguments in different environments; ~EApp(EIdent)~ is
  not shaped for it.

* Inference

- *Maybe: a signature's keywords pair with the ~defun~'s by position.* A
  different order unifies the wrong keywords (found in ~(text xml)~'s
  ~node-case~). Pair by name, or refuse with a message.
- *A lowercase nullary union case cannot be matched*: ~(blob "a")~ binds. Fix:
  resolve pattern constructors after parsing, or refuse lowercase nullary cases
  at the declaration (the prelude has none).

* Interop

- *A failed ~import/extern~ clause takes the rest of the import with it*: a good
  clause beside a bad one is reported unbound. Let the others stand, as a
  declaration group does.
- *Names that mangle alike in two modules* (~a-b~ in one, ~asubb~ in another)
  meet in C# through ~using static~. Checked within a module only.

* Equality and hashing

~Map~ and ~Set~ key on ~EqualityComparer<T>.Default~, not on ~std/eq~'s ~Eq~;
they agree only because a declared type's ~Eq~ is compiled into its ~Equals~.
Three cases still disagree (documented in ~Docs/prelude.org~, "Writing one by
hand"), each a lookup that silently misses:

- two cases of a union that ~=~ equates (~248_generic_materialization.bjo~);
- a specialized target, ~(impl (Eq (Pair %a %a)))~;
- a ~(where ...)~ of another trait.

One design closes all three: *the key's evidence as the collection's comparer*.
The CHAMP already takes an ~IEqualityComparer~, and ~Eq<T>~ could be emitted as
one (default interface methods forwarding to ~eq~ and ~eqsubhash~). Missing:
naming the evidence in scope, so ~map-empty~ and the other constructors (not
~map-set~ or ~map-ref~) gain ~(where (Eq %k))~. Pass ~null~ for the CLR-derived
~Eq~ to keep the JIT's devirtualisation. Do ~Ord~ and the ordered collections
the same way, not one without the other.

* Packages and projects

- *An executable names its dependencies by absolute path* (~BjolangModulePaths~
  in ~Build.fs~), so it only runs where it was built. Needs a decision about
  deployment layout.
- *Build output lands beside the source*, also inside ~.bjo/pkg/...~: two
  projects build one package twice, and a read-only package cannot be built.
  Needs staleness, the resolver table and the build record to know a second
  directory.
- *A relative import still means a path*, even across a package boundary.
- *No ~bjo add~, ~update~, ~remove~*: writing the manifest back would lose its
  comments and layout.
- *No shared clone cache*: it would be shared state, and nothing locks.
- *No registries, commit or branch pins, or pseudo-versions*; an untagged commit
  needs a path source.
- *One version of a package per build*: two copies would be two modules with one
  identity.
- *No ~bjo install~, ~test~ or ~clean~*, and one entry point per package. Tests
  are ~bjo run tests/x.bjo~, and ~simpletest~ exits 0 after a ~FAILURE:~.
- *Nothing locks ~.bjo~* against two ~bjo~ processes; the second fails loudly.
- *A version requirement on a path dependency is ignored*: a path source is an
  override.
