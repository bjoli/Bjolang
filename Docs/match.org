* Pattern Matching

Bjolang provides a powerful =match= expression for pattern matching and destructuring, along with a =case= form for simpler literal matching.

** The =match= Form

The =match= expression takes a target value and a sequence of clauses. Each clause consists of a pattern and a body to execute if the pattern matches.

#+BEGIN_SRC scheme
(match target
  (pattern body ...)
  (pattern #:when guard body ...)
  (pattern body ...))
#+END_SRC

The first clause whose pattern matches the target (and whose guard, if present, evaluates to true) is chosen. The body forms are evaluated in order, and the value of the last form is the result of the =match= expression.

*** Exhaustiveness

Matches in Bjolang are checked for exhaustiveness. If a match does not cover all possible values of the target type, the compiler will report an error. 

Note that clauses using guards (=#:when=) or views (=:view=) evaluate arbitrary code, and the compiler does not attempt to prove they cover specific cases. A match relying entirely on guards or views will need a catch-all pattern (like =_= or a binder) to be considered exhaustive.

** Pattern Forms

*** Literals and Wildcards

Literals match exactly themselves. The wildcard =_= matches any value and ignores it.

#+BEGIN_SRC scheme
(match x
  (42 "the answer")
  ("hello" "a greeting")
  (#t "true")
  (#\x "the character x")
  (#:foo "a keyword")
  ('symbol "a quoted symbol")
  (_ "anything else"))
#+END_SRC

*** Binders

A bare, lowercase identifier is a binder. It matches any value and binds it to that name within the clause's body.

A union case whose name begins with a lowercase letter and carries nothing is therefore matched as a list, ~(blob)~. Written bare where the scrutinee is its union, it is refused, since it would bind.

#+BEGIN_SRC scheme
(match x
  (0 "zero")
  (n #"non-zero: ${n}"))
#+END_SRC

*** Constructors

A bare, capitalized identifier is a nullary constructor. To match a constructor with arguments, use a list pattern with the constructor name as the head.

#+BEGIN_SRC scheme
(match opt
  (None "no value")
  ((Some x) #"got ${x}"))
#+END_SRC

*** Records and Structs

A record or struct is matched by its type name followed by the fields to look at, each written =(field-name pattern)=. Fields may be given in any order, and a field left out matches anything. A bare type name, like =Car=, matches every value of the type.

#+BEGIN_SRC scheme
(type (: Colour (Union Red Green Blue)))
(type (: Car (Record (: brand string) (: colour Colour) (: year int))))

(match car
  ((Car (colour Red) (brand b)) #"a red ${b}")
  ((Car (brand "volvo") (colour (or Green Blue))) "a cool volvo")
  ((Car (year y)) #:when (> y 2000) "a new car")
  (Car "some other car"))
#+END_SRC

A bare field name is shorthand for binding that field to a variable of the same name, so =(Car brand year)= means =(Car (brand brand) (year year))=. This makes destructuring short:

#+BEGIN_SRC scheme
(def (Point x y) p)
(match car
  ((Car brand (colour Red)) #"a red ${brand}")
  ((Car brand year) #"${brand} from ${year}"))
#+END_SRC

Field patterns are checked for exhaustiveness like constructor arguments, so matching =(Car (colour Red))=, =(Car (colour Green))= and =(Car (colour Blue))= covers every =Car=. The fields of an =#:opaque= type can only be matched in the module that declares it.

*** Collections

Bjolang supports pattern matching on lists, vectors, arrays, and tuples.

- *Lists*: =(List a b c)= matches a list of exactly three elements. You can also match empty lists using =()=, which is equivalent to =(List)=.
- *Vectors*: =(Vec a b)= or the literal syntax =[a b]=.
- *Arrays*: =(Array a b)= or the literal syntax =#[a b]=.
- *Tuples*: =(Tuple a b)= or the dotted pair syntax =(a . b)=.

**** The Spread Operator

You can use the spread operator =...= at the end of a sequence pattern to match the remaining elements.

#+BEGIN_SRC scheme
(match lst
  (() "empty")
  ((List head tail ...) #"head is ${head}, rest is ${tail}"))

(match vec
  ([x y rest ...] #"first two are ${x} and ${y}"))
#+END_SRC

*** Type Tests

The =:is= pattern matches if the value is of the specified type. It can optionally bind the typed value to a name.

A type test covers nothing in the exhaustiveness check, the same as a view. So a clause below =(:is System.Exception)= that tests for =(:is System.ArgumentException)= compiles, and no value reaches it. Put the more specific type first.

#+BEGIN_SRC scheme
(match obj
  ((:is System.String) "it's a string")
  ((:is System.Int32 n) #"it's the integer ${n}"))
#+END_SRC

*** Views

The =:view= pattern allows you to run a function on the matched value and match against the result.

Syntax: =(:view step pattern)=

The =step= can be a function or an accessor form (e.g., =(& .Property)=).

#+BEGIN_SRC scheme
(match text
  ((:view parse-int (Some n)) #"parsed integer ${n}")
  ((:view parse-int None) "not an integer"))
#+END_SRC

*** Logical Patterns

You can combine patterns using =or= and =and=.

- =(or p1 p2 ...)= matches if any of the patterns match. Because only one alternative runs, an =or= pattern alternative cannot run views or bind variables. Each alternative of a clause's =or= must be reachable: =(or 3 3)=, or =(or 3 4)= below a clause for =3=, is an error.
- =(and p1 p2 ...)= matches if all patterns match the value. Bound names must not be duplicated among the alternatives. The exhaustiveness check works out what the parts match together: =(and (:at-least 0) (:at-most 9))= covers the digits, and =(and 1 2)= matches no value, which is an error. A part that is a view or a type test decides by running code, so an =and= that holds one covers nothing.

#+BEGIN_SRC scheme
(match x
  ((or 1 2 3) "one, two, or three")
  ((and (:is int n) n) #"an integer: ${n}"))
#+END_SRC

*** Comparisons

=(:at-least lo)=, =(:at-most hi)=, =(:between lo hi)=, =(:greater-than lo)= and =(:less-than hi)= compare a number or a char with bounds. =:between= includes both ends: it is =:at-least= and =:at-most= together, as =version-between= is in a manifest. The bounds are number or char literals.

A comparison is a pattern like any other, so it may stand inside a constructor, a record field, a sequence pattern, =or= and =and=:

#+BEGIN_SRC scheme
(match points
  ((:less-than 0) "invalid")
  ((:between 0 59) "fail")
  ((:at-least 60) "pass"))

(match reading
  ((Some (and n (:greater-than 100))) #"too high: ${n}")
  ((Some n) #"ok: ${n}")
  (None "no reading"))
#+END_SRC

For an integer type or =Char= the comparison is a C# relational pattern in the =case= label, and the exhaustiveness check adds up the ranges: the first match above covers every =int= and needs no =_=, a clause whose range is already matched above it is an error, and a counterexample is a value in a gap, such as =0=. A match that holds a comparison is emitted as a =switch= statement, because C# proves the same ranges and refuses an arm of a switch expression it can prove unreachable.

For a =double= or a =decimal= the comparison is a binding and a =when= guard, and it covers nothing. A =double= can be NaN, which no comparison matches, so a match on one ends in a catch-all.

** The =case= Form

For simple dispatch against sets of literals, Bjolang provides the =case= macro. It takes a key expression and matches it against lists of literal data. It desugars into a =match= with =or= patterns.

#+BEGIN_SRC scheme
(case key
  ((1 2 3) "small number")
  (("a" "b") "a letter")
  (#t "true")
  (else "something else"))
#+END_SRC

Note that the data in a =case= clause *must* be literals (numbers, strings, characters, booleans, keywords, or quoted symbols). A bare identifier in a =case= datum list is not allowed, because in a regular =match= it would be interpreted as a catch-all binder. To match a symbol, use a quoted symbol (e.g., ='sym=).

The =else= clause acts as the wildcard catch-all and must be the last clause if provided.

*** Matching Keys in Maps and Collections (=Has= and =Has*=)

Bjolang provides the =Has= and =Has*= pattern macros in the standard prelude for matching against any =Refable= type (such as Maps or Vectors) by key.

The =Has= pattern checks if a collection contains a specific key, and if so, matches its value against a subpattern. Under the hood, it expands to a =:view= that uses =try-ref= and matches the resulting =Option=.

#+BEGIN_SRC scheme
(match my-map
  ((Has :my-key pat) #"The value of :my-key is ${pat}")
  (_ "Map did not contain :my-key"))
#+END_SRC

For matching multiple keys at once, you can use =Has*=, which takes pairs of keys and patterns, behaving like an =and= of multiple =Has= patterns:

#+BEGIN_SRC scheme
(match user-map
  ((Has* ("name" n) ("age" a)) #"User ${n} is ${a} years old")
  (_ "Missing name or age"))
#+END_SRC
